# 개발 착수 전 결정 현황 감사

기준: P-001~046과 현재 카테고리 문서. 사용자 질문: 미결정 사항을 먼저 확정해야 하는지, 얼마나 남았는지.

## 현재 상태

핵심 거래·TIG·가입·저장소·영어 우선 등 제품 방향은 상당 부분 확정됐지만 구현 계약은 아직 완성되지 않았다. Day 1~10은 실행 가능한 최종 일정이 아니라 의존성을 드러내는 초안이다.
기존 질문 표에는 확정된 방향과 남은 세부 조건, 기술 조사, 후속 사업 검토가 섞여 있다. 미결정 행 수를 사용자에게 남은 질문 수로 제시하지 않는다.
P-001~046은 누적 결정 ID 46개이며 이 중 P-030은 보류됐다. 모든 항목의 구현·사실 검증이 끝났다는 숫자는 아니다.

## 사용자 결정과 별개로 확인할 사실 4개 묶음

1. 구독 기반 제3자 작업·TIG 보상·자동 실행 구조의 provider 허용 범위. 사용자 승인만으로 외부 조건이 충족되는 것은 아니다.
2. 실제 지원 버전의 플랜/세부 등급·한도 조회, 로컬 전달값의 신뢰 한계와 중복 구독 식별.
3. macOS/Linux/WSL2와 Windows 네이티브의 설치·로그인·실행·중단/복구 동작.
4. 외부 코드 실행 격리·자원 제한과 유료 provider API 없는 결과 검사/초안 인계의 최소 실행 가능성.

위 확인은 정책을 정하기 위한 조사·통제된 실험이며 본 제품의 전면 구현과 구분한다. 결과에 따라 관련 묶음의 추천안을 바꿀 수 있다.

## 개발자가 작성할 구현 계약

승인된 정책을 바탕으로 API 필드·상태 전이·DB 원장·기기 인증·이벤트 schema·재시도/멱등성·테스트를 설계한다. 사용자에게 모든 필드와 내부 함수의 선택을 질문하지 않는다.
스택·보안 경계·데이터 목적·비용처럼 사용자 결정에 영향을 주는 변경은 구체적 안으로 제시한다. 상세 설계를 숨겨 승인된 것으로 간주하지 않는다.

## 착수 기준 제안

- 10개 묶음의 제품 정책과 경계가 기록되고 관련 표·계약의 충돌이 정리됨.
- 사실 확인 4개 묶음의 근거와 미확인/불가 결과가 명확하며 해당 기능을 어떻게 진행할지 결정됨.
- 구현 계약·담당·출시 검증이 검토 가능한 상태로 작성됨.

이 기준을 만족하면 기능 구현을 시작하는 것을 추천한다. 사전 조사·영어 화면 시안·계약 초안 작성은 계속 진행할 수 있다.
신규 사실 때문에 정책 변경이 필요하면 근거와 영향을 기록한다. 현재 감사에서 사용자 정책을 새로 확정하거나 역할을 배정하지 않았다.

UX로 드러나는 미정 예시: “Your worker went offline.” 다음에 자동 재개·다른 수행자 매칭·TIG 복구 중 무엇이 일어나는지를 정해야 코드와 안내가 일치한다.

## 후속 승인 상태

P-047~055로 R01~07·R09·R10의 추천 규칙이 승인됐다. P-056은 R08 인사이트 축적 범위를 보완했으며 보존기간/동의/원문 외부 제공 세부는 미정이다. 사실 확인 4개 묶음과 구현 계약 작성은 남아 있다. 이 문서의 앞부분은 승인 전 감사 이력이다.

## 데이터 정책 전부 승인 후 현황

P-057~066으로 D01~D10 수집/분류/보존/삭제/동의 설정/접근/갱신을 확정했다. R08의 제품 정책 공백은 이 승인으로 채웠다. 현재 다음 작업은 새로운 포괄 질문 묶음이 아니라 기술/provider 사실 확인, 버전/견적 검토, 구현 계약과 운영 정책 문구 작성이다. 검증에서 새 제약이 발견되면 영향과 대안을 보고한다.

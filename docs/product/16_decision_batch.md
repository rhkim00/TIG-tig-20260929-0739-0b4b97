# 제품 결정 묶음 1 — 부분 답변 기록

P-035에 따라 한 번에 논의할 10개 항목이다. 아래 추천은 사용자 승인 전 구현 기준이 아니다. 실제 provider 가격·기술 지원을 검증했다는 의미도 아니다.

| 번호 | 질문 | 추천안/응답에 필요한 정보 | 관련 항목 |
| --- | --- | --- | --- |
| 1 | 주간 TIG 지급량을 어떤 산식으로 정할까? | 표준 미국 달러 월간 가격 1달러당 주 50 TIG를 초기 가설로 제안. 가상의 월 20달러 플랜이면 주 1,000 TIG. 연간 할인·실제 결제액은 적용하지 않는 안. 실제 플랜 가격/식별과 경제성 검증은 별도 | WC-01, P-032 |
| 2 | 지급받거나 벌어둔 TIG가 만료될까? | 베타에서는 둘 다 만료 없이 누적. 이해하기 쉽지만 발행/누적 추이 관찰 필요 | WC-05 |
| 3 | 구독이 종료되면 기존 TIG는 어떻게 할까? | 확인된 종료 이후 다음 주간 지급은 중단하고 기존 잔액은 유지. 단순 조회 실패는 해지와 구분, 실패 처리 세부 미정 | WC-01·05 |
| 4 | 외부 사용자 가입을 어떻게 열까? | GitHub 로그인으로 누구나 가입하는 공개 베타 | SCOPE-01, SEC-01 |
| 5 | 베타에서 비공개 저장소도 지원할까? | 첫 베타는 공개 GitHub 저장소만. 접근 권한 공유 범위를 줄이는 대신 비공개 프로젝트 사용자는 제한됨 | SCOPE-02 |
| 6 | 어떤 작업을 먼저 교환할까? | 버그 수정·테스트 추가·작은 기능 단위. 장시간 학습/GPU 작업과 프로젝트 전체 제작은 후속으로 제안 | SCOPE-03·04 |
| 7 | 어느 OS를 공식 지원할까? | 사용자가 원하는 필수 OS 확인. 일정상 macOS/Linux 우선, Windows는 WSL2 경로를 추천하되 실제 설치/실행 검증 필요 | AI-02 |
| 8 | 서비스 언어는 무엇으로 시작할까? | 한국어 UI와 안내로 시작. 글로벌 영어 지원은 후속 제안 | SCOPE-05 |
| 9 | 결과와 기한 알림은 어디로 보낼까? | 웹/연결된 CLI 표시 + 작업 제출·기한 임박 이메일. 별도 모바일 앱/푸시는 후속 제안. 실제 메시지 발송 승인이 아님 | QUOTA-02, OPS-04 |
| 10 | 10일 개발은 언제 시작하고 두 사람은 얼마나 일할 수 있을까? | 시작일·시간대와 유찬/륜호 각각 하루 가용 시간 필요. 답을 받아 일별 계획/역할 제안 작성 | PLAN-01·02·03 |

UX 예시: “주간 TIG가 지급됐어요” → “이 버그 수정 작업을 올려줘” → “결과가 도착했어요. 승인하거나 문제를 알려주세요.”
이 묶음으로 모든 출시 결정을 끝내는 것은 아니다. 데이터 범위·보안/약관 검증·플랜 증명·호스팅 예산·지급 경합·검사 실행 방식 등은 다음 설계안에 포함한다.

## 이번 답변 반영

- 1~5번과 9번: 답변 없음, 추천안을 확정하지 않는다.
- 6번: P-036으로 작은 작업 한정 제안 수정. 과부하/보안 위협 제외, AI 추론 중심 프로젝트 제작 포함 방향.
- 7번: P-037으로 macOS/Linux/WSL2 방향 동의. Windows 네이티브 조기/동시 제공 희망은 검증 후 일정 제안.
- 8번: P-038 영어 우선으로 한국어 우선 제안 대체.
- 10번: P-039 하루 가용시간 질문 제거. 시작일은 미답변.
- 추가: P-040 이용 데이터 축적과 투자/데이터 판매 전략 방향. 세부 제안은 [데이터 전략](17_data_strategy.md).

위 표는 최초 제안 기록이며 이번 답변 및 최신 확정 결정이 우선한다.

## 후속 포괄 승인 반영

“앞서 답하지 않은 부분은 너가 추천한대로 진행해”에 따라 1~5·9번은 P-041~046으로 확정했다. 10번 시작일에는 추천 날짜가 없었으므로 미정이다. P-036~040의 사용자 수정 의견과 전략 방향은 유지한다.

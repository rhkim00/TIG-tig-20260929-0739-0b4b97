기존 기준: No Git UX, No Prompt Engineering, No Model Expertise. 양측 자기 AI 사용 방향.
P-008: CLI와 웹을 동기화해 함께 사용한다. 아래 역할 배분과 동작은 추가 결정 전까지 제안이다.

## 중심 흐름 — P-014~016 반영

요청자는 하던 AI 대화에서 “Tokenisgold에 올려줘, 모델 조건은 …, 보상 1,000 TIG”라고 말한다.
수행자는 “여유 있는데 TIG 벌 작업 찾아줘”라고 말한다. P-024에 따라 작업 하나를 먼저 추천받고 Yes로 수락·시작한다.
“다른 작업”, “더 간단한 거”, “나중에”도 지원하며 웹에서 전체 마켓을 탐색할 수 있다.
AI가 맥락을 인계하고 P-025에 따라 수행자의 Yes 한 번으로 해당 작업의 수행·합의된 검사·수행내역서 작성·Git 제출까지 진행한다. 상세 성공/실패 UX는 [자연어 흐름](13_agent_workflow.md)을 따른다.
웹은 상태 확인·수정·결과 검토의 경로이며 매번 수동 양식 작성부터 시작하도록 강제하지 않는 방향이다.

## 게시 확인 정책 — P-022

명확한 작업·모델 조건·보상과 게시 의도가 있으면 추가 확인 없이 게시·TIG 예치를 처리한다.
UX 예시: “이 버그 수정, 지정 모델로 1,000 TIG에 올려줘” → “게시했어요. 1,000 TIG를 예치했습니다.”
예외: “보상은 몇 TIG로 할까요?”처럼 부족한 정보만 묻는다. 처리 완료 문구는 서버 성공 확인 후 표시한다.

## 수행·제출 승인 정책 — P-025

정상 완료 시 제출 전 확인을 다시 요구하지 않는다. 자동 제출과 평가·승인·TIG 정산, 요청자 저장소 병합은 별도다.
UX 예시: “Yes” → “시작했어요. 작업과 검사가 끝나면 수행내역서와 함께 제출할게요.”
제출 성공 확인 후: “코드와 수행내역서를 제출했어요. 평가·승인 후 TIG가 정산됩니다.”
진행이 막히면 사유와 필요한 행동을 안내한다. 실패·재시도·재개 세부 규칙은 추가 결정한다.

## 결과 검토·지급 — P-026

플랫폼 검사 후 변경 요약·검사 결과·미확인 항목을 보여준다. 요청자가 최종 승인하면 TIG를 지급하며 수정 요청도 제공한다.
요청자의 AI 사용량이 소진되어도 웹에서 검토·승인할 수 있어야 한다. 요약 생성 주체와 검사 실행 위치는 미정이다.
UX 예시: “검사 8개 통과, 미확인 항목 1개” → “승인하고 1,000 TIG 지급” → 정산 성공 후 “지급했어요.”
표시 수치는 예시다. 코드 병합은 별도다.
P-027: 검토 기한 48시간 미응답 시 자동 지급하며 운영자 검토로 넘기지 않는다.
UX 예시: “검토 기한까지 12시간 · 미응답 시 1,000 TIG 자동 지급” → 정산 성공 후 “기한이 지나 자동 지급했어요.”
P-028: 검토 중 수정 요청이나 분쟁을 접수하면 예치 TIG를 전액 복구하고 거래를 종료한다. 수정 왕복·보류 심사를 필수로 두지 않는다.
UX 예시: “요청한 동작이 안 돼.” → “1,000 TIG를 돌려드리고 작업을 종료했어요.”
버튼 문구 제안: “승인하고 지급” / “문제 있어요 · TIG 돌려받기”. “수정 요청”이 같은 수행자의 재작업을 보장하는 것처럼 안내하지 않는다.
기한 시작·알림 채널·검사 실패·지급 후 신고 조건은 추가 결정한다.

## 선제 알림과 초안 저장 — P-018~020

부족할 때 인계를, 여유가 있을 때 수행할 작업을 안내하는 UX를 추가한다. 임계값·채널은 미정이다.
작업 진행에 맞춰 초안을 보존하고, 소진 후 실제 사용 가능한 보조 모델이 있으면 인계서 정리에 활용하는 경로를 검토한다.
UX 예시: “사용량에 여유가 있어요. TIG를 벌 작업을 찾아볼까요?”
상세: [사용량·초안·보조 모델](14_usage_and_drafts.md).

## 세부 구현 제안과 미결정

웹은 가입·게시·탐색·승인·잔액을, CLI는 저장소 준비·AI 연결·테스트·Git 제출을 담당하는 구성을 제안한다.
동기화 후보: 연결된 기기/도구, Task 상태, 진행 요약, 테스트 결과, 제출 상태. 터미널 전체 로그의 웹 전송은 미확정이다.
P-010에 따라 웹 작업 수락 후 로컬 AI 자동 시작을 선호한다. 약관 준수와 도구별 실제 실행 경로는 UX-04·AI-05에서 확정한다.
P-009에 따라 이미 준비된 공식 도구·로그인을 활용해 추가 API key 입력과 반복 설정을 줄인다. [구체적 UX 제안과 검토](12_provider_review.md)를 참조한다.
P-014에서 기존 로컬 AI가 맥락을 활용해 TaskSpec을 만드는 중심 흐름을 확정했다. 웹 전용 보조 흐름 여부는 미정이다.

각 흐름은 시작 조건, 사용자 행동, AI/서버/로컬 동작, 성공 결과, 실패·복구를 표로 확정한다.
반복 사용의 3~4 interaction 목표와 최초 설치·인증 과정을 구분하여 설계한다.

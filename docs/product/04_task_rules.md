# 작업 상태와 운영 규칙

## 현재 기준

기존 기준: TaskSpec, 수락·제출·검증·승인/수정 요청, 실패·취소 흐름.
근거와 확정 결정은 [확정사항](00_confirmed.md)을 따른다. 아래 질문은 별도 결정 전까지 모두 미결정이다.

## 확정된 수행·제출 경계 — P-025

특정 작업의 Yes는 수행·합의된 검사·수행내역서 작성·Git 제출까지 승인한다. 정상 완료 시 추가 제출 확인은 없다.
제출 성공은 평가 통과·요청자 승인·TIG 지급·요청자 저장소 병합과 구분한다. 다음 작업 수락 권한으로 확대하지 않는다.
검사 실패 처리, 재시도·재개와 세부 상태 전이는 아래 질문에서 결정한다.

## 요청자 승인과 미응답 — P-026·027 / TASK-06

플랫폼 검사 후 요청자가 직접 승인하면 TIG를 지급한다(P-026). P-027에 따라 검토 기한 48시간 동안 미응답이면 예치된 작업 보상을 자동 지급한다.
미응답을 운영자 검토로 넘기는 이전 제안은 채택하지 않는다. 자동 지급이 코드 자동 병합을 뜻하지는 않는다.
UX 예시: “검토 기한까지 12시간 남았어요. 기한 내 응답이 없으면 수행자에게 1,000 TIG가 자동 지급됩니다.”
정산 성공 후: “48시간 동안 응답이 없어 수행자에게 1,000 TIG를 자동 지급했어요.” 금액은 예시다.

기한 시작 시점·알림 시점/채널·검사 실패 처리는 아직 미결정이다.
P-028: 결과 검토 중 수정 요청이나 분쟁이 접수되면 예치된 TIG 전액을 요청자에게 복구하고 거래를 종료한다. 해당 거래의 자동 지급 예약은 무효화한다.
지급 보류 후 수정 왕복이나 운영자 심사를 요구하는 이전 제안은 대체한다. 같은 거래에서 재제출 기한을 반복 연장하지 않는다.
서버 기준 기한과 직접 승인/기한 만료/수정 요청의 경합, 재시도 시 1회 지급을 TASK-08·WC-07에서 설계한다. 클라이언트가 꺼져 있어도 기한 정산이 동작해야 한다.

## 환불·종료 — P-028

요청자의 수정 요청/분쟁 접수 → 예치 TIG 전액 복구 → 거래 종료. 수행자에게 이 거래의 보상은 지급하지 않는다.
UX 예시: “요청한 동작이 안 돼.” → “1,000 TIG를 돌려드리고 이 작업을 종료했어요.”
수행자에게는 “요청자가 결과 문제를 접수해 거래가 종료됐어요. 이번 작업의 TIG는 지급되지 않았어요.”라고 결과를 알린다. 금액과 문구는 예시다.
이 결정은 검토 중인 예치금 정산에 적용한다. 이미 지급된 TIG 회수, 지급 이후 신고, 후속 새 작업 게시 여부는 별도이며 임의 실행하지 않는다.
작업·AI 사용량을 소비한 수행자가 보상 없이 종료될 수 있고 결과를 받은 뒤 환불을 악용할 유인이 생긴다. 남용 대응과 결과물 이용 조건은 미정이며, 추가 심사·증빙·자동 제재를 확정한 것으로 보지 않는다.

## 상태 흐름 제안

DRAFT → OPEN → CLAIMED → EXECUTING → SUBMITTED → VERIFYING → AWAITING_APPROVAL → COMPLETED.
P-028에 따라 검토 중 수정 요청/분쟁은 환불·종료 경로로 전이한다. 같은 Worker에게 수정 작업을 반복시키는 기존 후보 흐름은 대체한다.
환불 완료 상태명과 FAILED / CANCELLED / MATCHING 등의 실제 전이는 TASK-08에서 확정한다.
원본의 후보 상태 목록을 구현된 상태 머신으로 취급하지 않는다.

상태별 표에는 전이 주체, 허용 이전 상태, 완료 조건, TIG 이동, 재시도 키, 시간 제한을 반드시 함께 적는다.

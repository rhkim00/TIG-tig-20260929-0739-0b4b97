# 데이터 축적·제품 개선·사업 활용 전략 설계

P-040은 전략 방향이다. 아래 필드·수집·상품·동의 방식은 검토용 제안이며 아직 구현 또는 이용자 동의가 확보된 것은 아니다.

## 축적할 데이터의 연결 구조

| 단계 | 후보 데이터 | 활용 가설 |
| --- | --- | --- |
| 요청 | 작업 종류·언어·프레임워크·완료 조건·범위 버전·요구 모델/추론·TIG 보상 | 수요·난이도·가격 분포 |
| 추천·수락 | 노출/추천·수락·거절·매칭 대기·조건 일치 근거 | 추천 적합성·공급 부족 파악 |
| 수행 | 실제 관측 도구/모델/설정·증거 수준·시작/종료·활성 실행/대기·오류·지원 OS | 작업별 실행 특성·복구 개선 |
| 자원 | 가능한 CPU/RAM/디스크 지표와 측정 범위·중단 사유 | 로컬 과부하 예방·지원 범위 개선 |
| 결과 검사 | 제출 버전·검사 종류·실행 위치·성공/실패·미검증·산출물 변경 규모 | 완료 조건 충족·평가 데이터 |
| 정산 | 직접 승인/48시간 자동 지급/문제 접수 환불·실제 원장 결과 | 거래 신뢰·실패 유형·포인트 흐름 |
| 제품 이용 | 온보딩 단계·게시 성공·다음 주 재방문·획득 후 사용 | 사용자 활성화·반복 이용 |

task_id·제출 버전·event_id·관측 시각·schema/평가 버전·출처를 연결하는 구조를 제안한다. 네트워크 재전송을 새 거래로 중복 집계하지 않는다.
모델/사용량은 실제 조회·사용자 선언·추정·미확인을 구분한다. 없는 token 수를 추정값으로 조용히 채우지 않는다.

## 데이터 품질이 경쟁력의 조건

- P-027 자동 지급은 미응답 정책 결과다. 코드 품질 성공 라벨로 사용하지 않는다.
- P-028 환불도 요청자의 문제 접수 결과다. 수행자의 객관적 실패 또는 부정 행위를 확정하지 않는다.
- 직접 승인·검사 통과·실제 모델 실행 증거는 서로 다른 지표다.
- 작업 난이도·모델·도구·환경·사용자 선택이 다른 결과를 단순 비교해 모델 우열이나 인과 효과로 단정하지 않는다.
- 장시간 요청에서 AI 실행 시간과 대기 시간, 실제 token 사용과 구독 한도 사용률을 분리한다.

## 수집·보존·상품화 경계

운영 데이터, 선택적 원문 데이터, 외부 제공 데이터를 분리해 설계한다. P-021의 선택 프로젝트 로컬 인계 초안과 명시적 게시 전송 원칙은 유지한다.
전체 터미널·대화·소스·비밀키를 기본 분석 수집 대상으로 삼지 않는다. 항목별 목적·열람자·보존기간·삭제·출처/이용 권한·동의 버전을 함께 정의한다.
코드·인계서·수행내역서 원문을 외부 제공/학습 자료에 포함할지는 별도 결정이다. 서비스 사용이 곧 원문 판매 동의라는 전제로 설계하지 않는다.
가명 ID만으로 익명성을 보장하지 않는다. 소규모 집계·희귀 작업·텍스트의 재식별 가능성도 외부 제공 전에 검토한다.
판매 또는 공개 단계에서는 실제 대상 지역·데이터 권리·provider 조건과 이용자 고지/동의 요건을 확인해야 한다. 현재 판매 권리나 허용 여부를 확정한 문서가 아니다.

## 단계별 활용 제안

1. 베타: 핵심 거래 이벤트·검사 근거·정산 사유를 일관되게 축적하고 내부 대시보드에서 누락·정확성을 확인한다.
2. 제품 개선/투자 설명: 활성 사용자·완료 거래·반복 이용·TIG 순환과 출처가 설명되는 품질 지표를 집계한다.
3. 후속 상품 후보: 집계 시장 리포트, 충분한 비교 조건을 갖춘 실행/평가 데이터, 권리를 확보한 선택 참여 데이터셋. 판매 가능성·수요·가격은 아직 가설이다.

영어 UX 제안: “Task activity and check results help us improve matching. View data settings.”
선택적 외부 데이터 제공 동의 UX 제안: “Contribute eligible task data to research datasets.” 별도 선택이며 기본 설정·동의 범위는 미정이다.
확인 팝업을 매 거래마다 추가하지 않고 첫 설정과 접근 가능한 데이터 설정에서 목적과 선택권을 설명하는 안을 제안한다.

## 요청/프로젝트 인사이트 확장 — P-056

[인사이트 명세 초안](21_insight_spec.md)에 요청 분류·프로젝트별 관측 이용률·반복 이용·공급 부족·TIG 순환의 분자/분모·출처·버전을 정의했다. 보존/동의/접근은 P-057~066으로 확정됐다. 실제 판매는 후속 범위다.

## 승인 정책과 구현 명세 경계

P-057~066이 수집/분류/보존/삭제/선택 설정/접근/갱신의 제품 기준이다. 이 문서의 이전 미정/제안 표현보다 [확정 데이터 정책](22_data_decisions.md)이 우선한다. 개별 필드·집계 쿼리·삭제 작업/복원 재적용·권한 검증은 실제 구현 명세에서 검증한다.

P-008은 제품 구성과 동기화 방향을 확정한다. 통신 방식·갱신 주기·명령 전달·로컬 실행 승인·연결 끊김 처리는 추가 결정이 필요하다.

P-009의 API 미사용은 별도 과금 provider API에 관한 제품 범위다. Tokenisgold/GitHub API 통신은 별개다.
P-010은 provider 허용 확인 완료를 뜻하지 않는다. [공식 문서 검토](12_provider_review.md)의 사실·해석·미확인 항목을 구분한다.

## 유지할 기존 기획 원칙

근거: [원본 기획서](../../Tokenisgold_service_plan.txt), 특히 3·4·13~16·19·24·28·40·41절.

- 코딩 작업 교환을 먼저 제공하며 자연어 요청, TaskSpec, Git 자동화, 결과 승인 흐름을 지향한다.
- Requester와 Worker는 각자의 기존 AI에서 자연어로 요청·가용성을 전달한다(P-014·015). 구체적 연결 방식은 미정이다.
- AI 계정/구독/quota 자체가 아니라 검증된 AI 보조 작업을 거래한다.
- AI requirement는 추천값과 수동 지정, 특정 모델 또는 capability 조건을 지원하는 방향이다.
- 실행 증명과 결과 품질 검증을 구분한다. 검증 등급은 Verified / Client Verified / Attested로 설계한다.
- TIG는 작업 수행과 P-029의 주간 지급으로 획득하고 작업 요청에 소비한다. 현금 구매·출금·사용자 간 직접 송금은 제외한다.
- TIG 이동은 escrow와 ledger로 기록한다. 주간 공급 방향은 P-029이며 지급량·자격과 나머지 실패/취소 정산 세칙은 미정이다.
- Tokenisgold가 consumer AI credential을 수집하거나 구독을 pooling/routing하지 않는다.
- P-045: 첫 베타는 공개 GitHub 저장소만 지원하며 비공개 지원은 후속이다.
- 광고/스폰서는 초기 수익 모델 후보다. 10일 베타에서의 실제 구현 여부는 미정이다.

## 확정으로 취급하면 안 되는 이전 제안

- 유찬: API/Worker, 륜호: UX/Web 역할 분담.
- 자연어/로컬 AI 중심 흐름 외에 웹 전용 요청자를 지원할지 여부.
- 별도 데스크톱 앱 추가, 특정 OS만 지원하기, 약관 확인 없이 웹 버튼으로 AI를 자동 실행하도록 출시하는 결정. CLI+웹은 P-008, 자동 시작의 조건부 방향은 P-010을 따른다.
- Claim 독점/시간 제한, 수정 횟수, 가입 TIG, 보상 금액.
- 정확한 기술 스택, 호스팅 업체, 공개 베타의 세부 출시 기준.

## P-067 — 요청자 Git 인계 UX 우선 (2026-09-10)

사용자: “tig를 터미널로 설치하고 본인 git을 연결하면 … request.md와 같은 작업지침서를 tig의 규칙에 맞게 올리는 것이 먼저” 및 “오케이 너가 바로 진행해줄수있어?”로 구현 승인. 요청자의 기존 LLM이 명세·선별 맥락을 작성하고 TIG가 검사·공유 확인·Git 커밋/업로드·플랫폼 게시를 연결한다. 원본 프로젝트 작업 상태를 보존하고 게시 시점의 정확한 코드와 명세를 묶는다. 공개 저장소 범위 P-045 유지. 명확한 게시 지시의 승인 P-022를 반복 요구하지 않으며, 새 공개 저장소/공유 범위 등 빠진 승인은 구분한다. 륜호는 공동 개발자이며 필수 테스트 거래 상대가 아니다.

## P-068 — 단일 실행 대화형 요청자 (2026-09-10)

사용자가 명령이 너무 많다고 지적하고 tig 실행 후 폴더·업무 질문, 최초 Git/서비스 연결 안내, 로컬 AI 자동 호출과 자연스러운 터미널 UI를 요청했다. TIG가 빠진 정보를 묻고 명세 준비·확인·업로드를 내부에서 연결한다. 처음 연결을 기억하되 만료·계정/서버 변경 때 다시 연결한다. 공식 CLI를 통한 본인 요청 작성에 별도 provider API 과금 fallback을 두지 않는다. 기존 AI 대화 자동 상속 및 모든 provider의 지원을 가정하지 않는다. 새 공개 공유 범위와 실제 TIG 보상은 게시 직전 한 화면에서 확인한다.

## P-069 — 한글 답변·보상 선확인·질문 축소 (2026-09-10)

사용자는 TIG_test 업로드 시 영어 질문에 한글로 답할 수 있어야 하고, solve this에 보상을 적지 않았는데 다음 단계로 넘어가는 점과 질문 수·서버 주소 직접 입력을 지적했다. 요청 내용은 한글/영문으로 받으며 정해진 메뉴의 한글 답도 처리한다. 보상은 명확한 현재 사용자 요청 또는 별도 보상 답변으로만 확정하고, 누락 시 AI 작성 전에 묻는다. AI가 생성한 금액이나 프로젝트 자료의 금액으로 대체하지 않는다. 일반 사용자는 설치본이 알고 있는 서버에 연결하고, 주소 수정은 별도 설정에 둔다. 반복 폴더·계속 질문을 줄이고 새 파일 포함 및 최종 공개 공유·보상 확인을 유지한다.

## P-070 — 게시 확인 후 수행자 개발과 질문 최소화 (2026-09-10)

사용자는 실제 업로드를 확인하고 “많이 안물어보고 간단하게 절차 많이 없이 올리는게 베스트”라고 설명했으며 수행자 구현을 지시했다. 기존 P-022/025/052를 유지하면서 명확한 의도를 중복 확인하지 않고 보조 메뉴를 줄인다. 본인 요청을 활용한 수행자 개발·체험은 실제 TIG 자기 거래 지급 승인이나 필수 검사 우회가 아니다.

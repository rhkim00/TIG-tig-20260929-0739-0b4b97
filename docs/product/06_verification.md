# 모델 조건·실행 증명·결과 검증

## 현재 기준

기존 기준: Recommended/수동 모델 조건, 3등급 실행 검증, 결과 검증은 별도.
근거와 확정 결정은 [확정사항](00_confirmed.md)을 따른다. 아래 질문은 별도 결정 전까지 모두 미결정이다.

## 추천 표시 — P-024

수행자에게 적합한 작업 하나를 먼저 추천한다. 추천 순위 계산 방식은 별도 결정한다.
UX 예시: “로그인 세션 버그 수정 / 1,000 TIG / 등록한 도구가 요청 조건과 일치합니다. 시작할까요?”
프로필 조건 일치와 실제 모델 실행 검증은 구분한다. 추천 단계에서 실행을 검증했다고 표시하지 않는다.

## 플랫폼 평가와 수행 기록 — P-016

요청 대비 수행내역서, 코드·검사 결과, 난이도·시간 데이터를 플랫폼 평가에 연결한다.
P-026: 플랫폼 검사 후 요청자가 최종 승인하면 TIG를 지급한다. 검사 통과만으로 즉시 지급하지 않는다. 검토 기한 48시간 미응답 시에는 P-027에 따라 자동 지급한다. 기한 시작과 검사 실패의 처리 조건은 추가 결정한다.
변경 요약·검사 결과·미확인 항목과 증거 출처를 보여주고 승인 또는 결과 문제 접수를 받는다. P-028에 따라 검토 중 수정 요청/분쟁은 예치금 전액 복구·거래 종료로 처리한다. 요청자의 AI 가용량과 무관하게 웹 검토·승인이 가능해야 한다.
검사 실행 위치·통과 기준과 요약 생성 주체는 VER-06·07에서 정한다. 수행자의 자체 보고를 독립 검증으로 표시하지 않는다.
사용자 예시: “검사 결과와 미확인 항목을 확인하세요.” → “승인해줘.” → 정산 성공 후 “수행자에게 1,000 TIG를 지급했어요.”
난이도 추정·실행 metadata의 측정/선언/검증을 구분한다. 수집 세부 사항은 [자연어 흐름](13_agent_workflow.md)을 따른다.

## 검증 표현 원칙

클라이언트가 제출한 모델 이름이나 prompt hash만으로 provider가 실제 그 모델을 실행했다고 단정할 수 없다.
이는 설계상 구분해야 할 증거의 범위이며, 실제 제공 가능 수준은 어댑터 검증 후 결정한다.
유효한 실행 기록과 기능적으로 올바른 결과는 별도 조건이다.
기존 테스트 통과만으로 원래 버그가 해결되었다고 자동 판단하지 않도록 Task별 완료 조건을 결정한다.

## 결정 후 반영

관련 질문 ID에 확정 P-xxx를 연결하고, 동작·예외·완료 조건 및 영향받는 작업/계약을 갱신한다.

## 검사와 기산점 확정 — P-047

필수 검사 완료와 코드/내역서/검사 결과의 웹 열람 가능 시점부터 검토 48시간을 센다. 기한 내 필수 검사 미충족 시 환불·종료한다. 수행자 보고·로컬 검사·독립 CI 증거는 구분한다. 유료 평가 AI를 추가하지 않는다.
승인 원문과 범위는 [결정 묶음 2](20_decision_batch_two.md) 및 [확정 기록](00_confirmed.md)을 따른다. 이전 질문 표의 중복된 미정 표현보다 이 결정이 우선한다.

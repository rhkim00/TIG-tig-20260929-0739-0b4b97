## 중심 UX 업데이트

P-014~016에 따라 기존 AI 대화에서 작업을 게시하고, 수행자는 자연어로 가용성을 등록해 추천을 받는다.
상세: [자연어 작업 흐름](13_agent_workflow.md). 아래 웹/Task 상태 흐름은 이 경험을 지원하는 경로로 사용한다.

## 작업 범위 — P-036

작업의 크기만으로 프로젝트 제작을 제외하지 않는다. AI 추론 중심의 설계·코드 생성·프로젝트 제작도 포함하는 방향으로 검토한다.
GPU 학습 등 수행자의 로컬 과부하와 보안 위협이 있는 작업은 제외한다. 코드 생성 작업도 의존성 설치·빌드·테스트에서 CPU/RAM/디스크/네트워크를 사용할 수 있으므로 작업 이름만으로 안전하다고 판단하지 않는다.
제안: 큰 요청은 AI가 검토 가능한 단계와 완료 조건을 제안한다. 여러 유료 Task 게시·추가 예치로 자동 확대하지 않는다. 자원 상한·격리·중단·검사 기준은 별도 설계한다.
영어 UX 예시: “Build a booking app.” → “I drafted the scope and acceptance checks. This task excludes GPU training.” 실제 검사 가능한 실행 범위와 일치해야 한다.

## 출시 흐름 제안

가입 → Repo 연결 → 자연어 요청 → TaskSpec 확인 → TIG 예치·게시 → 수락 →
로컬 AI 작업 → 제출·PR·검증 → 수정 요청/승인 → TIG 지급.
이 흐름은 기획서의 중심이며 각 단계의 구현 범위와 예외는 아래 카테고리에서 결정한다.

원본 28절의 기능 목록을 범위 검토 기준으로 사용한다. 공개 베타 운영 항목은 OPS 질문에서 보완한다.

## 의존성과 일정 판단

- 계정/플랜 식별 → 지급 자격/금액 → 게시/예치 → 추천/수락 → 실행/제출 → 검사/정산 순서다. 웹은 같은 계약의 mock으로 병행한다.
- 자연어 연결 방식·격리·검사 실행 주체·48시간 시작점·데이터 범위가 확정되지 않으면 관련 구현 계약을 최종화할 수 없다. 미정은 [실행 계획](18_execution_plan.md)에 묶어 둔다.
- Windows 네이티브 지원은 Day 1부터 검증 대상으로 둔다. WSL2에서 통과했다고 네이티브도 지원한다고 표시하지 않는다. 같은 출시일 포함 여부는 실제 증거와 유찬 결정에 따른다.
- Day 1에서 provider 허용이 확인된다고 보장하지 않는다. 확인되지 않은 기능은 출시 가능으로 표시하지 않으며 유찬에게 영향과 대안을 제시한다.
- 큰 프로젝트·다중 OS·두 AI 어댑터·신뢰 가능한 구독 식별의 작업량이 크다. 검증 실패 시 날짜/범위 조정안을 제출하고 임의로 필수 기능을 삭제하지 않는다.

이 계획은 가용시간을 요구하지 않지만 두 사람의 작업량이 무한하다고 가정하지 않는다. 각 날짜의 검증 실패는 다음 의존 작업의 상태와 함께 기록한다.
구체적 PR 후보·출시 기준은 [실행 계획](18_execution_plan.md)을 따른다. 기존 TH-001~005는 초기 후보이며 완료/배정을 자동 변경하지 않는다.

## 결정 후 반영

관련 질문 ID에 확정 P-xxx를 연결하고, 동작·예외·완료 조건 및 영향받는 작업/계약을 갱신한다.

P-014~016으로 자연어 연동·소진 시 인계·가용성 추천·수행내역서·평가 데이터 요구가 구체화되었다. 현재 10일 표는 미승인 초안이며 이 작업량을 반영해 재산정해야 한다.

P-018~020으로 한도 관측·알림, 작업 이벤트 보존, 인계 요약, 가용 보조 모델 처리의 기술 검증/작업 분해가 필요하다. 공식 지원 문서와 실제 설치 버전의 동작을 구분해 일정에 반영한다.

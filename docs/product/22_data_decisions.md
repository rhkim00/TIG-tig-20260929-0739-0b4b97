# 확정 데이터 정책 — P-057~066

P-056의 요청/프로젝트 인사이트 축적을 구현 가능한 정책으로 좁힌다. 이미 확정된 주간 지급·거래 규칙·데이터 판매 후속 범위는 다시 승인받지 않는다.
사용자의 “전부 동의해”로 D01~D10을 P-057~066으로 확정했다. 아래 기간·동작은 승인된 제품 정책이며 법률상 의무/적합성 판단은 아니다. 실제 수집/운영 정책은 대상 지역·데이터 항목·권리 조건을 확인해 작성한다.

| 번호 | 확정 정책 | UX 예시/목적 |
| --- | --- | --- |
| D01 | 기본 사건 범위: 작업 게시·추천·수락·시작·중단·제출·검사·직접 승인·자동 지급·환불, 요청 유형·요구/관측 모델·추론·시간·TIG·프로젝트/기술 태그를 기본 운영/분석 사건으로 기록. 비밀키/전체 대화/터미널 전문 제외 | “Task activity helps us improve matching.” |
| D02 | 프로젝트 식별: 내부 분석에는 GitHub 저장소 ID와 내부 project_id를 연결. 프로젝트 이름/URL과 소유자는 권한 있는 운영/당사자 화면에만 표시하고 공개 통계는 프로젝트 유형/스택 단위로 표시. 같은 저장소 이름 변경은 연속 추적, fork는 관계만 기록하고 기본적으로 별도 프로젝트 | “Usage by project type” |
| D03 | 요청 분류: 기존 요청자 AI의 인계서에 주분류/보조 태그를 생성시키고 서버 규칙으로 검증. 신규 제작/기능/버그/리팩터링/테스트/리뷰/문서/설정/기타부터 시작. 분류 수정 가능, 원본/변경/분류 버전 기록. 별도 유료 분류 AI 호출 없음 | “Category: Bug fix · Edit” |
| D04 | 서비스 작업 자료: 게시된 인계서·수행내역서·검사 요약은 거래 종료 후 1년, 서버가 보관하는 코드 패키지는 종료 후 90일. GitHub 원본/PR은 별도 저장소 정책이며 플랫폼이 삭제 보장하지 않음. 삭제 요청은 D08 우선 적용 | “Code package available until …” |
| D05 | 분석 보존: 연결 가능한 세부 분석 사건은 1년, 검토된 비식별 집계와 인사이트는 장기 보존. 계산 기간·분자/분모·표본/결측·쿼리/분류 버전과 갱신 이력 저장. 원천 삭제 뒤 재현 가능한 범위의 한계를 표시 | 요청 종류 추세·프로젝트별 반복 이용·TIG 순환을 계속 비교 |
| D06 | 진단 로그/백업: 마스킹된 오류 로그 30일, 일일 백업 30일 순환. 삭제 처리를 복원 후 다시 적용해 삭제된 데이터가 부활하지 않도록 함. 인증 credential은 로그에 남기지 않음 | 장애 해결용 기록과 사업 분석 기록 분리 |
| D07 | 고지/선택: 가입 때 기본 수집·목적 요약과 상세 정책 제공. 선택적인 제품 행동 분석(화면 열람/클릭 등)은 별도 설정·기본 꺼짐, 거부해도 거래/주간 TIG 사용 가능. 원문 연구 제공은 기본 꺼짐이며 베타 수집 기능으로 추가하지 않음 | “Optional product analytics: Off” |
| D08 | 열람/삭제: Settings에 내 데이터 내보내기·삭제 요청 제공. 삭제 가능한 계정/프로젝트 원문과 연결 분석 데이터는 요청 후 30일 내 처리하는 제품 목표. 남은 TIG 정산/진행 거래는 기존 거래 규칙대로 정리하고 임의 소각/환불 규칙을 추가하지 않음. 정산 원장은 서비스 유지 중 보존하고 계정 종료 후 1년까지 최소 가명 거래 기록을 유지하며, 직접 식별정보 분리. 구체적 의무/예외는 운영 정책 검토 | “Export data · Request deletion” |
| D09 | 인사이트 접근: 내부 상세는 유찬/륜호의 역할 기반 관리자만, 사용자는 자신의 프로젝트 지표 확인. 공개 유형별 통계는 서로 다른 요청자 10명·작업 30건 이상일 때만 표시하는 초기 기준. 이 수치만으로 익명성을 보장하지 않으며 희귀 조합/재식별 가능성 추가 검토. 투자자 제공은 같은 공개 기준의 집계부터, 원문 판매는 후속 유지 | 표본 부족 시 “Not enough data yet” |
| D10 | 분석 갱신: 거래/원장은 즉시 기록, 운영 상태는 즉시 표시, 인기 요청·프로젝트 이용률·재방문·TIG 순환 집계는 매일 갱신. SQL/규칙 기반 지표·템플릿 요약으로 시작하고 AI 해석은 출처/생성 버전·검토 상태를 갖춘 후속 기능. 전체 GitHub 시장 점유율로 표현하지 않음 | “Updated daily · Last updated …” |

D07의 선택 행동 분석과 D01의 거래 운영 기록을 같은 것으로 취급하지 않는다. 개인정보/동의 문구 및 운영 기록의 처리 근거는 실제 정책 검토에서 확정한다.
D04 코드 자료 보존·D08 삭제는 GitHub에 이미 공개된 복제본까지 지울 수 있다는 약속이 아니다. 코드/결과물 이용 권한의 약관 내용은 별도 작성한다.
D09 관리자 접근은 승인된 역할 설계이며 현재 서비스/사용자 데이터 접근 권한이 실제 부여됐다는 뜻이 아니다.

## 이번 묶음과 별개로 진행할 근거 확인

provider 허용 범위, 공식 플랜/중복 구독 식별, OS별 실행·격리, 자원 상한·검사 경로를 확인한다. 검증 실패 시 미지원으로 숨기거나 임의 보상/지원 정책을 바꾸지 않고 영향과 대안을 제시한다.

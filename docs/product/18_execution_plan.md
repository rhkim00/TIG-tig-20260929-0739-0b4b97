# 공개 베타 실행 계획 — 초기 검토 이력

현재 실행 배정과 작업 의존성은 [전체 워크플로우](../coordination/WORKFLOW.md)와 [작업 보드](../coordination/BOARD.md)가 대체한다. 아래 미승인/미착수 문구는 초기 검토 이력이며 현재 상태가 아니다.


관련: [일별 계획](10_delivery.md), [확정 결정](00_confirmed.md), [데이터 전략](17_data_strategy.md).
이 문서는 계획 작성 요청에 따른 검토 결과이며 앱 구현·실제 담당 배정·계약 확정·출시 승인이 아니다.

## 역할과 수정 범위 후보

- 유찬: 공통 계약/루트 설정, 서버·DB·TIG 원장, 로컬 CLI·AI 어댑터·격리. 담당량이 큰 구간은 PR 단위를 먼저 분리한다.
- 륜호: 영어 웹 UX, GitHub/기기 연결 화면, 작업·마켓·결과·정산 화면, 알림/설치 안내·지원 OS 검증.
- 공통: 상대 PR 검토, 신규 계정 전체 흐름 검증. API/schema 변경은 먼저 계약 PR로 공유하고 mock/서버를 같은 버전에 맞춘다.
- 실제 배정은 유찬 승인 후 TH 작업 문서에 기록한다. 조율 AI는 공유된 Git/PR를 읽어 다음 실행 가능 작업을 제안한다. 상시 자동 스케줄러가 실행 중인 것은 아니다.

기능 PR에는 관련 이벤트의 누락/재전송 중복 검증을 포함한다. 모델/검사 결과를 선언과 실제 증거로 구분한다.

## 구현 계약 전 남은 결정 묶음

아래는 초안의 질문 주제 목록이다. 최신 통합 목록은 [착수 준비 감사](19_readiness_audit.md)의 R01~R10을 따른다. 현재 추천안을 자동 확정하지 않으며 질문은 P-035에 따라 묶어서 제시한다.

1. 48시간 검토 기한의 정확한 시작점과 검사 실패 시 정산 경로.
2. 한 작업의 수행자 수·동시 작업 수·수락 후 시작/실행 시간 제한.
3. 실행 중 quota 소진·접속 끊김에서 재개·반납·환불 기준.
4. 큰 프로젝트의 완료 조건·단계 분할과 보상 예치 범위.
5. 코드/인계서 공유 범위, 로컬 자원 상한·격리·네트워크 권한.
6. 가입/플랜 식별 실패·오프라인 시 주간 지급 처리와 중복 구독 검증.
7. 자동 초안 요약 빈도·보조 모델 사전 설정·사용량 알림 임계값.
8. 서버 검사 실행 위치와 요약 주체, API 없는 증거 수준 표시.
9. 데이터별 수집·보존/삭제·동의·권리 기록과 외부 제공의 후속 범위.
10. 기술 스택·호스팅 예산·실제 시작일·역할 배정·출시 승인 기준을 포함한 운영 구성.

## 공개 베타 출시 기준 제안

- 새로운 외부 계정 두 개로 가입→구독 연결→첫 TIG→작업 게시/예치→추천/Yes→두 도구의 실행/제출→검토/정산을 실제 지원 환경에서 시연한다.
- 자동 지급/환불/직접 승인·주간 지급의 중복·경합을 시간 제어 테스트로 검증한다. 실제 7일을 기다릴 필요는 없다.
- 확인 불가능한 플랜/모델/한도를 검증 완료로 표시하지 않는다. 지급 신뢰 기준의 제한을 문서화한다.
- 지원 OS별 설치·AI 연결·로컬 격리·Git·중단/재연결을 확인한다. Windows 네이티브와 WSL2 증거는 분리한다.
- 외부 코드가 허용되지 않은 경로/credential에 접근하거나 자원 상한을 넘는 경우 차단/중단을 확인한다. 실제 제한 수치는 승인 후 고정한다.
- 기기 권한·다른 사람의 작업 접근·위조 제출·중복 원장·복구 실패 등 주요 실패 사례에 대해 실행 증거를 남긴다.
- 과금 provider API 자동 전환 없이 동작하고, provider 허용 범위의 미확인 사항을 해소하거나 유찬이 기능/출시 범위를 조정한다.
- 실제 수집 필드가 안내/동의/보존 정책과 일치하고 직접 승인·자동 지급·환불을 서로 다른 결과로 집계한다.
- 배포·백업·복구·설치 안내·문의 동선을 준비한다. 최종 출시 여부는 유찬이 결정한다.

UX 성공 예시: “Post this project for 1,000 TIG.” → “Your task is live.” → 수행자 “Yes.” → “Submitted for review.” → 요청자 “Approve.” → “1,000 TIG paid.” 숫자는 거래 UX 예시다.

## 승인 갱신 — P-047~056

R01~07·R09·R10 승인으로 역할·핵심 정책·기술 방향·출시 원칙이 확정됐다. 위 미배정/미승인 표현은 최초 초안 이력이며 P-055와 개별 TH 문서가 최신 배정이다. 상세 PR 분할·실제 검증/구현은 미착수다. R08 보존/동의 세부는 추가 명세한다.

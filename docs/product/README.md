## 확정과 제안의 구분

- **확정**: 유찬이 명시적으로 결정한 내용. 결정 ID, 근거, 영향을 함께 기록한다.
- **확정(조건부 방향)**: 사용자 선호는 확인됐지만 명시된 조건 충족은 미확인. 구현·출시 허용 확인과 구분한다.
- **기존 기준**: 원본 기획서의 확정 원칙. 변경 결정이 없는 한 유지한다.
- **제안**: AI/팀원이 검토용으로 제시한 내용. 승인된 구현 범위로 취급하지 않는다.
- **미결정**: 답이 필요한 항목. 예시/선택지는 결정이 아니다.
- **대체됨**: 이후 결정으로 바뀐 내용. 기존 결정의 이력과 대체 ID를 보존한다.

`00_confirmed.md`는 확정 결정의 기준이고, 각 카테고리는 관련 원칙·제안·질문을 관리한다.
문서가 충돌하면 최신 사용자 지시를 반영하고 확정 결정 → 카테고리 문서 → 기존 기획서 순으로 갱신한다.
파일 날짜만으로 제안을 확정사항보다 우선하지 않는다. 실행 중인 세션의 최신 지시는 미병합 상태여도 따른다.
다른 세션에 전달하려면 commit/push하고 해당 PR을 읽게 해야 한다. main에 병합되기 전에는 main만 읽어서는 최신 결정을 알 수 없다.

## 대화 후 갱신 절차

1. 사용자의 답에서 확정된 범위만 추출한다. 인접한 제안을 함께 승인한 것으로 간주하지 않는다.
2. `00_confirmed.md`에 P-xxx 결정, 근거 발언, 영향받는 질문 ID를 기록한다.
3. 관련 질문을 확정 결정 링크로 바꾸고 동작·예외·완료 조건에 반영한다.
4. 영향받는 기술 계약·작업 문서·일정과 기존 제안의 충돌을 수정한다.
5. 문서 검사를 실행하고 변경을 commit/push하여 조율 PR로 공유한다. 최종 병합은 유찬의 결정에 따른다.
6. P-035에 따라 결정 질문을 약 10개씩 묶고 추천안·UX 예시를 함께 제공한다. 답변한 범위만 확정하고 미답변을 승인으로 보지 않는다.

모든 주요 카테고리를 초기 목록으로 잡았지만 구현에서 새 의존성이 발견되면 질문을 추가한다.
현재 질문의 답을 채운 것은 아니다. 숫자·기간·지원 OS·배포 비용 등의 기본값을 몰래 확정하지 않는다.

## 현재 중심 시나리오

요청: “이 작업 Tokenisgold에 올려줘. … 보상 1,000 TIG.”
수행: “TIG 벌 작업 찾아줘” → 추천 → “Yes” → AI 수행·기록 제출 → 평가·정산.
대화에서 동작과 정책을 논의할 때마다 짧은 UX 예시를 함께 제시한다(P-013).

## 현재 확정 상태와 다음 작업

P-001~066에 제품·거래·TIG·지원 범위·담당·데이터 정책을 기록했다. P-030 미사용량 캠페인은 보류다. 이 숫자는 구현 완료나 외부 사실 검증 건수가 아니다.

- 거래 규칙·기술/운영 방향: [결정 묶음 2](20_decision_batch_two.md), P-047~055 승인.
- 요청 종류·프로젝트별 인사이트: [인사이트 설계](21_insight_spec.md), P-056 방향과 P-057~066 정책 적용.
- 데이터 수집/보존/삭제/설정/접근/갱신: [확정 데이터 정책](22_data_decisions.md), D01~D10 전부 승인.
- 담당: 유찬 서버/CLI/AI/정산, 륜호 영어 웹/온보딩/알림/설치 UX. [작업 보드](../coordination/BOARD.md)와 개별 TH 작업은 TODO이며 실제 착수/완료를 뜻하지 않는다.

이제 승인된 정책을 다시 묻기보다 기술 근거와 구체적 구현 계약을 작성한다.

1. [provider 검토](12_provider_review.md): 구독 기반 작업 교환/자동 실행 허용 범위 확인.
2. 공식 플랜/모델/한도 조회·중복 구독 식별의 실제 가능 범위와 신뢰 수준 확인.
3. OS별 설치·격리·자원 상한·AI 실행/중단·검사 경로를 통제된 샘플로 검증.
4. 승인 정책을 API/DB/상태/원장/기기 인증/이벤트·보존/삭제 계약과 테스트로 구체화.
5. 실제 버전·호스팅 견적·가격표를 확인하고 [Day 1~10 계획](10_delivery.md)과 [PR/출시 검증안](18_execution_plan.md)을 실행 단위로 정리.

[착수 준비 감사](19_readiness_audit.md)의 최초 미결정 목록은 이력이다. R 묶음과 데이터 D 묶음은 승인됐으며 남은 사실 검증·명세 작성·운영 문구 검토를 구분한다. 검증 결과가 승인된 범위/비용/사용자 경험을 바꾸는 경우에만 영향과 대안을 제시한다.
최종 출시·병합은 유찬이 결정한다. 실제 프로그램 구현이나 제공사 허용·법적 적합성 검증 완료를 선언하지 않는다.

# 사용량 알림·자동 인계 초안·소진 후 보조 모델

확인일: 2026-09-09. 제품 방향 P-018~021을 기록한다. 아래 기술 근거는 공식 문서 확인이며 실제 어댑터 검증/구현 완료는 아니다.
현재 provider의 별도 과금 생성 API 미도입(P-009), 구독 사용·작업 중개의 약관 조건(P-010)은 유지한다.

## 사용자가 요청한 기능

- 사용량이 부족해지는 사용자에게 작업 인계를 안내한다.
- 사용량 여유가 있는 사용자에게 TIG를 벌 작업을 제안한다.
- Tokenisgold 설치·연동 후 사용자의 작업 진행에 맞춰 인계 초안을 자동 보존하는 방향이다.
- 주 모델이 제한에 도달해도 다른 허용 모델이 실행 가능하면 인계서 정리에 활용하는 경로를 검토한다.

## 유료 생성 API 없이 가능한 관측 경로

| 도구 | 공식 근거 | 적용 한계 |
| --- | --- | --- |
| Codex | [App Server](https://learn.chatgpt.com/docs/app-server)의 account/rateLimits/read, account/rateLimits/updated는 사용 비율·window·reset과 복수 bucket을 제공한다. | 로그인/권한/버전과 반환 필드를 확인해야 한다. bucket과 모델이 1:1이라는 뜻은 아니다. |
| Claude Code | [status line](https://code.claude.com/docs/en/statusline)의 rate_limits는 5시간/7일 사용률·reset 정보를 제공한다. 로컬 상태줄 실행은 API token을 소비하지 않는다. | 구독 종류와 첫 응답 이후 등 제공 조건이 있고 각 window가 없을 수 있다. 이미 끝난 reset 정보나 미조회 상태를 현재 값으로 표시하지 않는다. |
| Codex 작업 이벤트 | [Hooks](https://learn.chatgpt.com/docs/hooks)에 UserPromptSubmit/PostToolUse/Stop/Interrupt 등 이벤트가 있다. | 지원되는 이벤트·버전을 기준으로 보존한다. 강제 종료나 연동되지 않은 세션까지 항상 포착한다고 약속하지 않는다. |
| Claude Code 작업 이벤트 | [Hooks](https://code.claude.com/docs/en/hooks)에 tool 완료·실패 등의 이벤트와 실행 결과가 있다. | 파일 편집뿐 아니라 shell에서의 변경도 고려해야 한다. 기존 사용자 hook/status line 설정을 덮어쓰지 않는다. |

“API 없이”는 유료 provider 추론 API key를 발급받아 생성 요청을 하지 않는다는 뜻이다.
공식 로컬 프로토콜/metadata와 Tokenisgold 서버 통신은 사용할 수 있다. provider와의 네트워크 통신이 전혀 없다는 뜻이 아니다.
문서상 지원 사실과 설치된 버전의 실제 노출 범위, Tokenisgold 구조의 허용 여부는 별도로 확인한다.

## 과거 미사용량과 마케팅 — P-030 / QUOTA-04

P-031로 이 캠페인과 보너스는 보류했다. 아래는 후속 검토용 근거다. 기존 사용량 부족/여유 알림 P-018을 취소한 것은 아니다.

2026-09-09 추가 공식 확인: [Codex App Server](https://learn.chatgpt.com/docs/app-server)의 `account/usage/read`는 누적 token 활동 요약과 일별 사용 bucket을 제공한다. 값과 일별 목록은 null일 수 있으며 지원 인증·설치 버전·실제 계정의 조회 범위는 검증 전이다. 사용 기록 조회 경로가 있다는 사실이 구독 시작 이후 모든 기록 또는 ChatGPT 전체 사용 범위를 보장하지 않는다.
[Claude Code status line](https://code.claude.com/docs/en/statusline)은 현재 5시간/7일 사용률·reset을 제공한다. 이번 확인 문서는 관련 rate_limits 기능에 v2.1.251 이상과 지원 구독/첫 응답 조건을 명시한다. 이 경로에서 가입 전 전체 구독 기간의 사용 이력을 가져오는 기능은 확인하지 못했다.

설계상 해석: 사용한 token 수를 알아도 당시 제공된 총 token 한도를 모르면 미사용 token 수를 뺄셈으로 계산할 수 없다. 현재 사용률을 과거 모든 주에 적용하거나 구독료를 미사용 비율로 곱해 실제 금전 손실이라고 표시하지 않는다.
연동 후에는 공식 조회로 관측된 window/bucket의 사용률·확인 시각·reset을 기록하는 설계를 검토한다. 관측 공백·한도 변경·추가 reset을 구분하고 5시간/7일의 중첩 비율을 더하지 않는다. reset 전 마지막 값은 그 시점의 남은 비율이지 실제 소멸된 총량의 확정값이 아니다.

UX 제안(수치는 예시): “지난 주간 한도 초기화 10분 전 마지막 확인에서 60%가 남아 있었어요. 이번 주 Tokenisgold의 TIG 지원으로 필요한 작업을 맡겨보세요.”
자료 부족 시: “이전 구독 기간의 미사용량은 확인할 수 없어요. 연결 후 확인 가능한 사용 현황을 보여드릴게요.”
TIG는 Tokenisgold가 지급하는 자체 혜택이다. provider의 구독료 환불·공식 보상·소멸 token 복원이나 고정 환산으로 표현하지 않는다. 원문 대화·인증 정보를 수집하지 않고 필요한 지표와 동의·보존 범위를 QUOTA-03/SEC-06에서 정한다. 공유 카드는 선택 기능 제안이며 자동 게시하거나 전체 계정 정보를 공개하지 않는다.

## 사용량의 단위

- 구독의 사용 한도: 5시간·주간 등 window별 사용률, reset, 제한 상태.
- context window 사용률: 현재 대화에 넣을 수 있는 문맥 공간. 구독 잔여량과 다르다.
- 실제 input/output token: 해당 호출/세션의 사용량. 구독의 남은 token 수를 직접 의미하지 않는다.
- TIG: Tokenisgold의 작업 포인트. 위 단위들과 고정 환율을 가정하지 않는다.

데이터 후보: provider/tool/version, 관측 시각, source, bucket_id, window, used_percent, reset_at,
limit_reached, plan(공식 제공 시), freshness, available/unknown/error 상태.
필드가 없으면 unknown이다. 0% 또는 100%로 채우지 않는다. 사용률 예시는 완료할 수 있는 작업 수의 보장이 아니다.

## 알림 UX 예시 — 수치와 빈도는 미확정

부족 알림:

> 현재 5시간 사용 한도의 90%를 사용했어요. 최신 인계 초안을 저장했어요. 남은 작업을 Tokenisgold에 맡길까요?

여유 알림:

> 현재 조회된 사용 한도에 여유가 있어요. 조건에 맞는 1,000 TIG 작업을 찾아볼까요?

조회 불가:

> 지금은 구독 잔여량을 확인할 수 없어요. 마지막 확인은 20분 전입니다. 여유가 있다면 작업 추천을 요청할 수 있어요.

첫 두 문구는 실제 최신 관측값과 저장 성공이 있을 때만 사용한다.
같은 사용자가 시점에 따라 Requester/Worker 역할을 바꾸므로 알림은 고정된 계정 유형에 종속하지 않는다.
여러 window 중 하나가 제한에 도달하면 다른 window에 여유가 있어도 “작업 가능”이라고 단정하지 않는다.
높은 잔여율만으로 해당 Task를 완료할 수 있다고 보장하지 않는다. 현재 개인 작업과 사용자의 수행 의사도 고려한다.
임계값, 연속 알림 방지, 수신 거부/조용한 시간, 채널, 관측 주기는 QUOTA-01~03에서 결정한다.

## 자동 저장과 AI 요약을 분리하는 설계 제안

1. **작업 이벤트 보존:** 연동된 프로젝트에서 요청 변경, AI 응답 완료, 코드 수정, 검사 결과, 중단 등 지원 이벤트를 로컬에 증분 저장한다. 저장 자체는 LLM 생성 호출이 필요 없다.
2. **인계 초안 갱신:** 기존 AI가 작업을 마무리할 때 목표/완료/남은 일/검사 상태를 갱신하도록 연동한다. 이 요약은 사용량과 지연을 추가할 수 있다. 매 tool 호출마다 별도 AI를 실행하는 것은 미확정이다.
3. **게시용 인계서:** 최신 요약과 이후 변경 기록을 합쳐 실제 게시 직전에 코드 상태·완료 조건을 확인한다.

초안 후보 항목: user goal, completed work, next steps, constraints, evidence/tests,
repo/base SHA, changed/untracked files 중 선택된 범위, 마지막 기록 event ID·시각, 요약 기준 시각, 이후 변경 여부.
오래된 요약과 최신 파일을 혼합해 “최신 인계 완료”라고 표시하지 않는다.

UX 예시:

> 인계 초안이 저장됐어요. 마지막 요약 이후 수정된 파일 2개는 게시 전에 확인해 주세요.

설치만으로 모든 도구·모든 프로젝트에 접근할 수 있다고 가정하지 않는다.
P-021: 최초 연결에서 사용자가 선택한 프로젝트의 초안을 로컬에 자동 저장한다.
“올려줘”라는 명시적 게시 요청이 있을 때 필요한 인계 내용만 서버로 전송한다.
이 결정은 초안/작업 맥락의 저장·전송 범위다. 기기 연결 상태·사용량 metadata의 동기화 정책은 별도이며 QUOTA-03에서 정한다.
저장할 상세 필드, 보존기간·삭제·켜기/끄기와 공개 Git에 포함할 범위는 추가 결정한다.

확정 방향의 UX 예시:

> 이 프로젝트의 인계 초안을 내 기기에 자동 저장합니다. 게시를 요청하면 필요한 내용만 전송합니다.

## GPT-6 → GPT-5.6 Sol 예시의 정확한 의미

GPT-6 계열에서 GPT-5.6 Sol로 바꾸는 것은 **모델 변경**이다. 같은 모델에서 High → Low로 바꾸는 **추론 강도 변경**과 구분한다.
[OpenAI 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-sol)는 GPT-5.6 Sol과 reasoning.effort 옵션을 구분한다. API 모델 정보가 개인 구독의 한도 분리를 증명하지는 않는다.
[Codex 사용량 문서](https://learn.chatgpt.com/docs/pricing)는 한도에 가까워졌을 때 더 작은 모델로 사용 기회를 늘리는 방법, 한도에 도달한 활성 turn의 제한적 지속을 설명한다.
완전 소진 이후 GPT-6에서 GPT-5.6 Sol로 새 turn을 열면 반드시 작동한다는 보장은 확인하지 못했다.

사용자가 경험한 전환은 활용할 후보로 유지한다. 정확한 계정·플랜·한도 bucket·현재 세션 상태에서 허용되는 모델이 있는지 확인한다.
같은 전체 한도가 막힌 경우 모델/effort 변경으로 새 작업이 가능해진다고 가정하지 않는다.
안전장치/한도 우회, 계정 순환, 비공개 endpoint 호출, 유료 API 자동 전환을 구현하지 않는다.

## 보조 모델과 저장 초안의 우선순위 제안

- 평소: 작업 기록과 인계 초안을 자동 유지한다(P-019).
- 사용량이 적을 때: 인계 안내를 표시한다(P-018).
- 주 모델 제한 시: 공식적으로 사용 가능한 보조 모델이 있고 전환 동의를 얻은 경우, 인계서 정리에만 사용한다(P-020).
- 보조 모델도 사용할 수 없거나 확인할 수 없으면: 저장된 초안과 변경 목록으로 사용자에게 보충/게시를 제안한다.

보조 모델 예시:

> 현재 모델의 사용 한도에 도달했어요. GPT-5.6 Sol을 사용할 수 있는지 확인한 뒤, 인계서 정리에만 사용할까요?

사용 가능 확인 후 성공한 경우:

> Sol로 인계서를 정리했어요. 실제 수행자에게 요청할 모델 조건은 원래 지정한 그대로입니다.

“인계서 작성 모델”과 “외주 작업 수행에 요구하는 모델”은 별도 필드다. 사용자 동의 없이 요청 모델 조건을 낮추지 않는다.
모델 전환 동의의 일회/사전 설정 여부, 시도 횟수, 요약 분량/사용량 한도는 FALLBACK-01에서 결정한다.

## 보조 기능 기준 확정 — P-053

이벤트 로컬 증분 저장·AI 응답 완료 시 요약 갱신, 별도 요약 최대 10분당 1회/변경 없으면 생략. 보조 모델 첫 설정 선택·기본 꺼짐. 필수 한도 중 80% 이상 부족, 모두 확인되고 30% 이하 여유, 동일 알림 6시간 억제. 실제 metadata 제공 여부·사용량 예산 세부는 검증한다.
승인 원문과 범위는 [결정 묶음 2](20_decision_batch_two.md) 및 [확정 기록](00_confirmed.md)을 따른다. 이전 질문 표의 중복된 미정 표현보다 이 결정이 우선한다.

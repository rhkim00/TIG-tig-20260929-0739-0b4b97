# Day 1~4 실행 계약 v0.1

TH-027의 구현 계약이다. 기존 task_api/storage_and_ledger 문서는 전체 서비스 목표이고 이 문서는 현재 HTTP/DB/CLI 구현 범위를 구분한다.
제품 기준 P-001~066. 런타임 스키마의 기준은 `packages/contracts/src/index.ts`, HTTP 공개 명세는 `GET /v1/openapi.json`이다.
아래 구현 선택은 이번 사용자 구현 요청에 따른 검토 가능한 코드이며 최종 제품 변경·병합·출시 승인을 대신하지 않는다.

## 구현 스택과 개발 조건

Node 24.20.0, TypeScript, npm workspaces, Fastify 5, React 19/Vite 8, PostgreSQL 16. 정확한 의존성은 package-lock.json에 고정했다.
현재 호스트의 Node 18을 교체하지 않고 이 worktree `.local/runtime/`에 Node를 설치했다. 시스템 PostgreSQL 설정도 바꾸지 않고 로컬에 개발 DB만 실행했다.
설치 DB는 PostgreSQL 16.15이며 테스트도 PostgreSQL에서 실행한다. 메모리 DB의 성공을 동시성 검증으로 대체하지 않는다.

기술 근거: [Fastify Node 지원](https://fastify.dev/docs/latest/Guides/Migration-Guide-V5/), [Vite 설치 조건](https://vite.dev/guide/), [GitHub OAuth/PKCE](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps), [Codex 공식 app-server](https://learn.chatgpt.com/docs/app-server).

## HTTP와 인증

| 구분        | 구현                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 로그인      | GET /auth/github → state cookie/PKCE → GET /auth/github/callback. GitHub read:user만 사용, access token은 신원 조회 후 저장하지 않음 |
| 세션        | HttpOnly/SameSite=Lax, production Secure, 7일 만료, DB에는 token hash만 저장. mutation은 동일 Origin 필수                            |
| 기기        | POST /v1/device-authorizations → 웹에서 code 승인 → token polling. 10분 만료·1회 발급·해제 즉시 무효                                 |
| 기기 권한   | 본인 TIG/작업 API에 bearer 사용. 기기 승인/해제는 웹 세션만 가능. 특정 외부 작업 실행 권한을 주지는 않음                             |
| 개발 로그인 | TIG_DEV_MODE=true에서만 /v1/dev/sign-in. loopback host/origin·비production 조건을 시작 시 강제. 운영 모드에는 route 없음             |
| 프로젝트    | 공개 GitHub metadata 확인, repo ID로 연결; 게시 시 공개 여부와 base SHA 재확인                                                       |
| 게시        | POST /v1/artifacts → POST /v1/tasks. 작업/예치/outbox는 동일 DB transaction                                                          |
| 취소        | POST /v1/tasks/{id}/cancel, expectedVersion. OPEN/요청자만, 원장 전액 복구                                                           |
| 조회        | /v1/me, /wallet, /wallet/entries, /projects, /tasks, /tasks/{id}, /connections, /devices                                             |
| 설정        | PATCH /v1/me/data-settings, optionalProductAnalytics 기본 false. 선택 이벤트 수집기는 아직 없음                                      |
| 관측        | POST /v1/subscription-observations. strict allowlist, server_verified 입력 거부, entitlement나 TIG 발급으로 승격하지 않음            |

일반 사용자 mutation은 actor+route+Idempotency-Key+정규화 body hash로 중복을 방지한다. 동일 키의 다른 body는 409다.
인증 시작/콜백·기기 코드 발급/폴링은 인증용 1회 nonce/DB lock으로 보호하는 별도 교환 절차다. 이 절차에 일반 거래 idempotency 응답을 저장하여 token을 복제하지 않는다.
공통 오류 `{code,message,retryable,requestId}`. raw credential/provider 응답/DB 상세 오류는 반환하지 않는다.
OpenAPI는 현재 거래 스키마 중심이며 OAuth/기기 교환의 상세는 이 표와 구현·테스트를 함께 따른다. 미구현 claim/실행/정산 endpoint를 동작 가능한 것으로 표시하지 않는다.

## 정확한 금액과 주간 발행

TIG를 최대 소수 2자리 문자열/SQL NUMERIC으로 표현한다. US 월간 가격을 cents 단위로 정확히 ×50하므로 19.99 USD → 999.50 TIG가 반올림 없이 표현된다. 이 숫자는 합성 테스트용이며 실제 플랜 가격이 아니다.
원장 tx의 합계 0, 음수 사용자/예치 잔액 금지, 계정 잔액과 entry 합계 일치, 원장 과거 UPDATE/DELETE 금지를 PostgreSQL 제약/trigger로 확인한다.

`plan_prices`+`entitlements`는 신뢰한 검증자가 확인한 구독 전용이다. 공개 HTTP 입력으로 추가할 수 없다. 현재 자동 provider 자격 검증자는 아직 구현되지 않았고 production 지급표를 채우지 않았다.
Worker는 검증 유효기간 내 verified 자격의 첫 주기/7일마다 지급한다. provider별 anchor·주기 unique, 복구 시 최신 주기 하나만, 플랜 변경은 다음 주기, cancelled/unavailable/검증 만료는 신규 발행 중지다.
단순 로컬 플랜 관측이 실제 결제/고유 구독 증명이라고 오인해 TIG를 발행하지 않는다. production 자동 주간 지급 출시는 이 증명 연결이 선행돼야 한다.
개발 seed는 명시적 development.seed 원장으로 샘플 TIG를 만든다. 실제 구독 지급/획득 이력과 혼동하지 않는다.

## 로컬 초안과 게시

`checkpoint`는 선택 프로젝트의 tracked 파일/미커밋 변경/삭제 목록을 저장한다. untracked는 명시한 목록만 포함한다.
숨김 경로/env/key/인증 파일·심볼릭 링크·바이너리·일부 비밀 패턴은 제외한다. 제외 목록을 CLI 출력에 보여준다. 비밀 패턴 검사는 모든 비밀의 부재를 보증하지 않는다.
현재 개발 전송 한도는 100개 파일, 텍스트 파일당 200 KB, 합계 1 MB다. 큰 프로젝트를 제품 정책으로 금지한 것이 아니라 검토할 초기 전송 한도다. 확대/패키지 저장소는 후속 구현에서 조정한다.
파일명/내용 hash/source와 삭제 목록을 manifest hash에 포함하고 서버에서 재검증한다. 추적된 삭제는 별도로 기록한다.
초안은 사용자 로컬 상태 폴더의 0600 파일로 atomic replace. `watch`는 증분 변경 시 저장하고, 응답 완료 시 기존 AI가 `checkpoint --summary`를 호출한다. 전체 대화는 읽지 않는다.
`canRequestSummary`는 변경 여부와 10분 간격을 검사하며 별도 요약 모델 호출 자체는 아직 구현하지 않았다. 따라서 현재 자동 유료/보조 추론은 발생하지 않는다. fallback 기본 off.
`post --spec`는 필수 조건을 확인한 뒤 저장된 인계서/TaskSpec을 게시한다. 추가 추론 없이 같은 명세/초안으로 재시도할 수 있다. 누락된 명세로 먼저 파일을 전송하지 않는다.
요청 레이아웃 `tree`(P-071 제안, 2026-09-16): `request.json`의 `layout:"tree"`는 요청 브랜치 `tig/requests/<id>`가 요청자의 작업 트리 전체(미커밋 변경·미추적 포함, 보호 경로·`.github/workflows/**`·비밀 파일 제외)를 담은 부모 없는 커밋이고 `request.md`/`request.json`이 루트에 있음을 뜻한다(`code/` 없음). 서버는 문서 2개만 artifact로 등록하고, 게시 검증은 커밋이 부모 없음·루트 blob 2개가 100644이며 sha1이 artifact 내용과 같음만 확인한다(비재귀 tree 조회; 나머지 트리는 서버가 보지 않는다). `layout`이 없거나 `bundle`이면 기존 전수 비교 그대로다(bundle의 request.json 바이트 불변). 수행자 CLI는 모든 요청에 `X-Tig-Client`/`X-Tig-Capabilities: request-tree`를 보내고, `tree` 작업의 claim은 이 capability가 없으면 409 `CLIENT_UPGRADE_REQUIRED`로 claim 전에 거부돼 작업은 OPEN을 유지한다. `GET /v1/tasks/{id}`는 당사자에게 `gitRequest`와 `layout`을 함께 돌려주며 웹은 tree 요청을 브랜치·커밋으로, report.md만 미러된 제출은 "변경 파일은 PR에 있음"으로 표시한다. 요청 브랜치는 일회용이며 main에 merge하지 않는다.

## 공식 사용량 관측과 실행 제한

`sync-codex`는 공식 app-server의 initialize/account/read(refreshToken=false)/account/rateLimits/read만 호출한다. 임시 빈 cwd, credential 파일 직접 읽기/대화 읽기/추론/로그인/로그아웃/사용량 reset 없음.

model→quota bucket 대응을 추정하지 않는다. 기본 bucket=codex이며 미확인 창은 unknown으로 남겨 잘못된 여유 알림을 피한다.
`observe`의 알림은 필요한 창 중 80% 이상이면 부족, 모두 알려지고 30% 이하면 여유, 동일 알림은 6시간 억제다.

첫 단계는 관련 파일 수·최소 40·최대 98, 이후 절반씩). 크기는 좁히기와 초안 호출이 같은 자로 잰다: `draftPayloadBytes`(local-ai.ts; 요청문·clarification·파일·제외 목록을 담은 JSON, `not selected` 항목은 세지 않고 그 밖의 제외 항목은 100개까지만 나열하고 나머지는 `excludedNotListed` 개수로 보냄)가 `DRAFT_CONTEXT_LIMIT`(180 KB)에서 12 KB 여유를 뺀 값 이하여야 한다. 한도를 넘을 때 60 KB 초과 파일이 있으면(다른 파일이 남는 한) 그것부터 뺀다(`N file(s) over 60 KB left out`). 그래도 로컬 AI가 `DraftContextExceeded`를 내면 자동 흐름은 공유 파일을 우선순위대로 절반으로 줄여 `Narrowing to N files to fit the drafting context.` 한 줄 뒤 다시 호출하고, 파일 하나가 남아도 안 맞을 때만 기존 메시지로 멈춘다. `Sharing N files (M new)`의 M은 실제 공유된 새 파일 수다(34,000개 미추적 파일의 211 GB 저장소에서 초안이 중단되던 문제, 2026-09-16). 제외 목록은 `details`에서 본다. **초안 도구**: 하나면 그것; 둘이면 `usageAvoids`(세션 `limitHit`, Codex 관측 low, 6h 내 Claude 상태줄 관측 low) 제외 후 세션 도구→최근 도구 순, 둘 다 low면 세션 도구가 아닌 쪽, 판단 근거가 없으면 최근 도구→발견 순 첫 도구(질문 없음, 사용자 결정 2026-09-16 "no일 때만 입력"). 도구별 첫 사용은 `consent` 문구를 한 줄 안내로 보여주고 `prefs`에 기록할 뿐 확인을 묻지 않는다. **목적지(D1, 2026-09-16)**: 프로젝트 첫 실행에 `origin`이 공개 GitHub 저장소이고 `gh api repos/<name>`의 `permissions.push`가 참이면 그 저장소를 쓰고(`destination:"origin"`), 아니면 `<login>/<폴더명>-tig-requests` 공개 요청 저장소를 묻지 않고 생성·연결한다(`destination:"delivery"`; 사유와 함께 한 줄 안내 `Destination: github.com/<repo> (your repository | request repository)`; 다른 저장소는 `tig setup`에서만 선택). 검토 화면의 마지막 줄들은 tree 요약이다: 목적지·브랜치, `Tree: N files (size) = HEAD + a changed + b new: 이름…`, 폴더별 새 파일 수·용량, ignored-but-tracked 목록, `Excluded: 경로 (사유)`, cherry-pick 안내(`tig/requests/*`는 main에 merge 금지). `details`는 HEAD 대비 변경(M/A/?/D, 200줄)과 제외 전체를 보여 준다. 커밋이 없는 폴더는 빈 시작 커밋을 묻지 않고 만든다(한 줄 안내). **수행자 AI**: 요청문에 있으면 그대로, 없으면 세션 도구→초안 도구 후보에서 첫 유효 제안(Claude 규칙: docs/test/review/setup 또는 8개 이하 bug→sonnet/medium, 20개 초과 또는 build/feature/refactor 8개 초과→opus/high, 그 외 opus/medium; Codex: 로컬 카탈로그 첫 모델·기본 effort)을 묻지 않고 채우며 요약에 근거를 표시; 제안이 불가능할 때만 `provider / model / effort` 입력. effort는 도구 어휘 그대로(Codex 카탈로그 `supportedReasoningEfforts`, 2026-09-16 관측 `low|medium|high|xhigh|max|ultra`; Claude `--effort` `low|medium|high|xhigh|max`)이며 사용자 입력의 `light`/`extra high`/`maximum` 등은 `normalizeEffort`가 정식 이름으로 바꾸고, Claude에 없는 값(`ultra`, `ultracode`)은 입력으로 받지 않는다(사용자 지적 2026-09-16). **보상**: 사용자가 직접 쓴 요청문의 금액(`statedReward`; `AUTO:` 요청문은 커밋 제목·경로이므로 검색하지 않는다, P-069) → 세션에 저장된 금액 → `estimateReward`(build/feature/refactor 150, bug/test/setup 80, docs/review 50, other 80; 파일 6~20개 ×1.5, 20개 초과 ×2, 10 단위 반올림, 잔액 초과 시 잔액으로 상한, 잔액 1 미만이면 질문). AI가 낸 금액(`draft.rewardTig`)과 프로젝트 자료 속 숫자는 쓰지 않는다. **검토 화면** `Is this the work you want to hand off?`: 제목·Based on·Work·Done so far·Done when(3개)·Worker AI(근거)·Reward(근거)·기한·공개 저장소·파일 수·포함된 새 파일. `yes` 게시, `no`(아니요/아니)는 "바꿔 달라"는 뜻 — `What should change? (describe it; Enter keeps the request)` 한 질문만 하고(Enter면 같은 요약으로 돌아가며 AI 호출 없음), 답은 세션 파일 `revision`에 줄 단위로 누적 저장돼 이후 모든 초안 호출의 clarification에 붙어 request.md를 다시 쓰게 한다(저장된 `candidate`·`manifestHash`·`pending`을 버리고 `Rewriting request.md with <tool> …` 한 줄 뒤 실제 AI 재호출; 한도 fallback·동의 규칙은 첫 초안과 같다). 새 요약에는 `Revised with: <지시>` 줄이 붙고 입력한 보상·수행자 AI는 그대로다. `revision`은 `later` 뒤에도 남아 pending 요청을 다시 초안할 때 적용되며, 게시하거나 새 설명 `tig "…"`을 줄 때만 지워진다. `details` 전문·파일 목록, `later` 보관(다음 실행에서 바로 검토; 안내는 `tig`와 `tig request show <id>`(스크립트용 publish 명령 출력)만 적는다 — `tig request publish`는 `--approve <digest>`가 필수라 그대로 실행되지 않으므로), 숫자 입력은 보상 변경, `provider / model / effort` 입력은 수행자 AI 변경 — 입력값을 세션 파일에 `reward`+`rewardByUser`/`workerAi`로 저장하고(`prefs.lastReward`도 갱신) 저장된 초안(`candidate`)·같은 파일 선택으로 재준비하며 근거는 `set by you`(AI 재호출·초안 도구 선택·로그인·동의 없음; pending 요청의 검토 화면에서 바꿔도 같다). 그사이 프로젝트가 바뀌어 저장된 스냅샷(`manifestHash`)이 맞지 않으면 `The project files changed since this request was prepared; drafting it again with your terms.` 한 줄 뒤 일반 흐름으로 다시 초안을 쓰되, AUTO 요청문이 다시 생성돼도 사용자가 입력한 금액·수행자 AI는 유지한다(초기화는 새 설명 `tig "…"`을 줄 때만). 이미 Git에 게시된 스냅샷의 조건은 바꿀 수 없다. `claude-notes`는 Stop hook의 `cwd`·`last_assistant_message`만 읽으며 비밀 패턴이 있으면 저장하지 않고 항상 exit 0이다(보조 수단).
수행자 제안(P-015/P-024/P-025/P-053): `tig work --market`은 `toolSignals`(Codex `account/rateLimits/read`, Claude 6시간 이내 상태줄 캡처; 실패·미캡처는 unknown)로 설치 도구별 신호를 얻고, `recommendTask`가 열린 Git 요청(타인, fixture 제외) 중 하나를 고른다: 신호가 low인 도구는 제외, 요청 도구가 사용 가능하면 그것, 아니면 다른 사용 가능 도구로 대체(제안문에 명시); 점수 = 여유(spare) 100 + 정확 일치 10 + min(9, 보상/100), 동점은 최신. 제안문 `Take "<title>" for <reward> TIG with <tool> (<model> / <effort>)? — <근거>`에 `yes`(네)면 `marketWork(id, …, {provider, assumeYes:true})`로 수락 확인·도구 선택 없이 수락→시작→AI→Git→제출, `next`는 건너뛰고 다른 요청, `no`/빈 입력은 종료. `--watch --every N`(기본 10분)은 여유 신호가 있을 때만 제안하고 `no` 뒤 6시간 억제, 작업 후 계속, Ctrl+C 종료. `yes` 뒤 `marketWork`가 실패하면(프롬프트를 기다리는 사이 다른 수행자가 수락, AI 시간 초과, push/PR 실패 등) `--watch`는 `proposeOnce({keepGoing:true})`가 잡아 프로세스를 끝내지 않는다: `"<title>" was not finished: <오류>. It is set aside; I'll keep watching for other requests`(수락 전 실패) 또는 `… It is accepted for you; run tig work <id> to continue and submit it`(수락 뒤 실패; INTERRUPTED면 `tig resume <id> and then tig work <id>`)를 다음 확인 시각과 함께 한 줄로 알리고, 그 id를 skipped에 넣어(다른 작업이 끝날 때까지 다시 제안하지 않음) `outcome:"failed"`로 다음 주기를 계속한다. Ctrl+C(`Cancelled`)는 잡지 않는다. `--market`은 그대로 던져 exit 1. 이미 맡은 작업이 있으면 안내문이 id와 명령을 명시한다: `you are already working on "<title>" (<state>); run tig work <id> to continue and submit it, then tig proposes the next request`. AI 실행 제한은 20분(`WORKER_AI_TIMEOUT_MS`)이며 실행 중 5분마다 heartbeat로 수락과 version을 갱신한다. 직접 id 지정(`tig work <id>`)은 기존 질문 유지. **한도 기억**(`limits.ts`): 로컬 AI가 `usage limit|session limit|rate limit|quota|한도` 메시지로 실패하면 `<state>/limit-<provider>.json`에 reset 시각(`resets 11:30am (UTC)` 형식을 UTC로 해석, 없으면 5시간 뒤)을 기록하고, reset까지 `toolSignals`·`usageAvoids`가 그 도구를 low로 본다(reset이 지나면 파일 삭제). `marketWork`는 실행 중 한도 실패 시 다른 설치 도구(한도 기록 없을 때)로 대신할지 한 번 묻고, 요청자 초안(`wizard`)은 묻지 않고 다른 도구로 재시도한다(화면에 표시). **대체 시 모델**(`selectWorkerAi`): 요청 도구와 실행 도구가 다르면 Codex는 카탈로그의 첫 비숨김 모델(요청 effort 지원 시 그대로, 아니면 기본 effort), Claude Code는 요청 모델이 `opus|sonnet|haiku|claude-`로 시작할 때만 그대로, 아니면 `opus`(effort는 Claude 단계일 때만 그대로, 아니면 medium)를 쓰고 `Substituting … with …`로 표시, 제출 `execution`에는 실제 도구·모델을 기록한다. **양쪽 터미널 알림**(`notices.ts`, P-053): 서버가 사용자별로 쌓는 알림(`task.claimed`/`task.submitted`는 요청자, `task.reopened`/`settlement.paid`/`settlement.refunded`는 요청자+수행자; `GET /v1/notifications`)을 `NoticeBoard.show(ui)`가 `readAt`이 없는 것만 오래된 순으로 최근 `MAX_NOTICES`=10개까지 `HH:MM · <title> — <body> → <다음 명령>` 한 줄씩 출력하고(더 있으면 `N older updates: tig inbox`), 출력한 id만 `POST /v1/notifications/<id>/read`(key `notice-read:<id>`)로 읽음 처리한다(실패 무시). 다음 명령은 type 접미사로만 정한다: `submitted`→`tig task <id> · tig approve <id> --yes`, `paid`/`approved`→`tig status`, `reopened`/`expired`→`tig work <id>`, `claimed`/`refunded`/`issue`/그 외→`tig task <id>`. 연결 전·오프라인·형식 오류는 조용히 빈 결과. 프로세스 안에서 한 번 출력한 id는 다시 출력하지 않는다(읽음 처리 실패로 서버가 계속 unread로 내려도). 연결 위치: `tig`(루트, TTY일 때만)는 `startWithNotices`로 마법사 전에, `tig work`는 `ensureConnection` 직후 같은 board로 한 번, `--watch`는 `WatchDeps.notices`로 매 주기(억제 중인 주기 포함) 새 것만 — 오류가 나도 watch는 계속되고, 도구가 없어 제안이 없어도 종료하지 않으므로 요청자도 `tig work --watch`로 제출 알림을 받을 수 있다. 알림은 알리기만 한다: 승인·수락은 사용자가 친 명령으로만. **tree 요청의 수행(`worker-agent.ts`, 2026-09-16, D3/D4/D7)**: `readWorkerPackage`는 `request.json`의 `layout`으로 분기한다 — `tree`면 artifact는 문서 2개뿐이어야 하고 98파일/180 KB 한도와 `code/` 필터를 건너뛰며, `bundle`(또는 `layout` 없음)은 기존 JSON 경로 그대로다. tree 흐름: heartbeat 시작 → `git clone --depth 1 --single-branch --branch tig/requests/<id> --separate-git-dir <trial>/git <repo> <trial>/ws`(`GIT_CONFIG_GLOBAL=/dev/null`, 10분 제한) → `rev-parse HEAD === baseCommit`이 아니면 sha로 fetch 후 detach, 실패 시 `REQUEST_BRANCH_MOVED` → tig가 `<trial>/git/config`를 고정 내용(hooksPath=빈 폴더, fsmonitor=false, gpgsign=false, filter/diff 드라이버 없음, origin만)으로 덮어쓰고 이후 모든 git 호출은 `--git-dir/--work-tree` + `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1`(네트워크 호출만 시스템 config 유지) → **AI 실행**(`runWorkerAgent`, cwd=ws, env=`subscriptionEnvironment`, 20분, `spawn({detached})` + 프로세스 그룹 SIGKILL / Windows `taskkill /T`): Codex `exec --ignore-user-config --ignore-rules --sandbox workspace-write --ephemeral --skip-git-repo-check -C <ws> -c approval_policy="never" -c sandbox_workspace_write.network_access=false …(shell_tool·unified_exec만 켜고 나머지 features는 초안과 같이 off) --output-schema <report> --output-last-message <file> -`; Claude `-p --output-format json --no-session-persistence --safe-mode --restricted --strict-mcp-config --permission-mode acceptEdits --permission-prompts none --tools Read,Edit,Write,Glob,Grep --model --effort --json-schema <report>`(둘 다 `--help`에서 플래그 존재를 먼저 확인, `--bare`·`--dangerously-*` 없음). 프롬프트는 루트 request.md 구현과 짧은 보고(`summary·suggestedTests·limitations·commandsRun`)를 지시한다 → `collectWorkspaceChanges`: `git add -A` → `request.md`/`request.json` 변경은 `checkout HEAD --`로 원복 → `protectedPathReason`(files.ts, 요청 트리와 같은 표)·심볼릭 링크·gitlink·`_authToken`이 든 `.npmrc`는 index에서 빼고 `dropped:[{path,reason}]` → 변경 텍스트 파일(UTF-8, ≤1 MB) 전부 `containsSecret` → `RESULT_SECRET_DETECTED`(push·submit 없음, ws 보존) → 변경 0건이면 `<tool> made no change; nothing submitted. Run tig work <id> to try again.`(D4, 제출 없음) → `git commit -m "Tokenisgold result for task <id>"` → `workspace-candidate.json`(재실행 시 커밋이 있으면 AI 재호출 없이 재사용) → `renderWorkspaceReport`(diff --stat, 변경/삭제 목록, dropped/restored, mirrored 여부, 도구 신고 commandsRun) → `report.md`도 비밀 검사 → `publishWorkerResult({workspace:{gitDir,commit}})`가 결과 커밋의 부모==baseCommit을 확인하고 git dir에서 push(fork 경로 동일), PR 본문=report → submit artifact = `mirrorFits`(텍스트만, ≤97개, 각 ≤200,000자, 합 ≤900 KB, `safePath`)이면 `code/<path>`+`report.md`와 `deletedPaths: code/<p>`, 아니면 `report.md`만(D7, 부분 미러 없음); `execution`은 실제 provider/model/effort, 모드(`agentic`)는 report·receipt에 기록. 요청자의 개인 체험(`personalWork`)도 tree면 같은 작업 공간 흐름으로 로컬 커밋과 `report.md`까지만 만든다. `doctor`는 `workerAgentReadiness`로 두 도구의 sandbox 플래그를 확인하고 `Execution` 줄에 실제 격리 방식을 표시한다.
`doctor`는 Node 24·Git·GitHub CLI(2.21+ 및 `gh auth status`)·Codex/Claude Code(설치·버전·구독 로그인)·Tokenisgold 연결(`/v1/me`)을 읽기 전용으로 검사한다. 로컬 AI는 하나만 준비돼도 통과이며 비밀 값은 출력하지 않는다.
`sandboxDoctor`는 현재 Linux namespace 실행 가능성을 읽고 실행 불가를 반환한다. 성공하더라도 자원·credential broker 검증이 없으면 실행을 활성화하지 않는다. 실제 untrusted task runner는 아직 미완료이며 미격리 fallback은 없다.

# 실제 첫 게시 UX 검토 — 2026-09-10

사용자 정의: 많이 묻지 않고 절차가 적은 게시. 기준은 [실제 게시 검증](../verification/TH-035-worker-trial.md). 추가 업로드 로그는 메시지에 없으며 정확한 질문 횟수는 알 수 없다.

## 관찰과 반영

| 문제/근거 | 처리 | 상태 |
|---|---|---|
| 게시 마지막에 동등한 4개 메뉴를 읽어야 함 | 공개 대상·보상 요약 뒤 게시 질문 하나, details/later 보조 답변 | 0.5.0 구현 |
| 명세의 context에 반복된 요청/결정 위임이 기록됨 | 질문은 한 번에 묶고 Enter 또는 판단 위임이면 관찰된 코드의 가정을 문서화하도록 지시. 해결 불가능한 범위를 계속 인터뷰하지 않고 저장 후 안내 | 0.5.0 구현, 실제 모델의 질문 감소 효과는 후속 측정 |
| 보상은 사용자가 안 적어도 필요 | 명시 금액 재사용, 없을 때만 먼저 한 번 질문 | 0.4.1 유지 |
| 서버/계정/폴더 정보의 반복 | 내장 서버·저장 연결·같은 폴더 자동 재사용 | 기존 구현 유지 |
| astra가 실제 실행 모델 ID가 아님 | 수행자 시작 전 공식 catalog 후보와 full ID를 함께 표시. 모호함/미지원은 중단 | 개인 체험에 구현 |
| 분류가 other이나 실제 범위는 코드 개선/검증 | 후속: AI 분류 지침과 taxonomy 평가. 게시된 조건은 임의 수정하지 않음 | 제안 |
| 최초 프로젝트/Git 공개 연결은 아직 단계가 있음 | 후속: 이름/기본 공개 대상/선택 파일/보상을 하나의 미리보기에 통합해 동의를 묶기. 기존 공유·예치 동의 범위 확대를 암묵 승인으로 다루지 않음 | 제안 |

## 목표 예시

```text
❯ tig
› 어떤 작업을 맡길까요?
❯ 이 파일 개선해서 올려줘. astra medium, 400 TIG.
[TIG: 선택 코드에서 명세 작성, 이미 알려진 조건 재사용]
› 400 TIG · 공개 파일 3개. 게시할까요?
❯ 네
✓ 게시 완료 [작업 링크]
```

설명용 한국어 예시이며 실제 UI 기본 언어는 영어다. 모든 정보가 명확한 게시 지시의 중복 확인 제거 방향 P-022는 유지한다. 아직 확인하지 않은 공개 파일 범위나 예치 조건은 알려야 하므로 이번에는 마지막 확인 하나를 남긴다. 세부 내용 보기·나중에·초안 폐기는 사용자가 필요할 때 접근한다.

후속 측정 제안: 최초/재방문별 사용자 답변 횟수, 명세 작성 시간, 명세 추가 질문 비율, 게시 이탈률과 되돌리기. 원문 대화 전부 수집 대신 건수·시간·실패 사유를 기존 동의/데이터 정책 범위에서 설계한다. 이번 코드가 이 지표 수집을 새로 배포한 것은 아니다.

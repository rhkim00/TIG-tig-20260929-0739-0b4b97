## 사용자 승인과 범위

사용자가 실제 수행 이전에 요청자 설치·Git 연결·request.md와 코드 Git 게시를 먼저 완성하도록 승인했다. 같은 사용자가 두 테스트 역할을 맡을 수 있으며 륜호는 필수 거래 상대가 아니다. 기존 AI가 맥락을 정리하고 TIG CLI가 규칙·검사·Git·게시를 담당한다. 별도 provider 추론 API는 사용하지 않는다.

## 구현 계약

init으로 공개 GitHub 전달 저장소 연결 또는 명시적 공개 생성. prepare는 구조화된 요청 입력에서 request.md·코드 snapshot·공유 preview와 승인 digest를 로컬 생성. publish는 확인된 고정 snapshot만 별도 요청 branch에 올리고 artifact/task API로 등록한다. 원본 index/branch/미커밋 작업 보존. 기존 Git history를 새 전달 저장소에 복제하지 않는다. 서버는 Git commit의 파일 tree와 업로드 패키지 일치를 검증한다. 실패 후 같은 요청 재시도로 중복 게시·예치를 방지한다.

## 검증·다음 행동

실제 임시 Git/bare remote·HTTP/PostgreSQL·설치 CLI로 전체 게시·실패/재시도·명세 불일치·공유 제외를 검사한다. GitHub transport 대체 테스트와 실제 외부 공개 게시를 구분한다. 실제 프로젝트를 임의로 공개하지 않는다.
유찬은 이번 요청자 흐름 구현·검증, 륜호는 변경 계약을 읽고 기존 TH-030 온보딩 후속. 실제 AI 수행은 별도 후속이다.

## 구현 결과

CLI 0.3.0 init/instructions/request prepare/show/publish와 서버 Git 일치 검증·웹 요청 링크 구현. 설치 CLI 포함 44개와 desktop/mobile E2E 6개 통과. [검증 보고](../../verification/TH-033-requester-git.md), [사용법](../../REQUESTER_QUICKSTART.md)을 따른다. 실제 외부 공개 push와 기존 AI 자연어 대화 자체는 별도 확인 필요. PR/main 병합·실제 AI 수행 완료를 주장하지 않는다.
